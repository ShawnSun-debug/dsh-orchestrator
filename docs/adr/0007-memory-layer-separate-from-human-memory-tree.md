# 0007 记忆层独立于人类记忆树

## 状态

已决定（2026-11-05）

## 背景

主代理只活在单个会话里：换一个会话，编排状态、对项目的理解、跨项目的事实全部从零开始，
用户不得不在新会话里重新交代背景。宿主唯一的跨会话沉淀是 `~/.dsh/AGENTS.md` 与它索引的
`memory/topics/*.md`，但那是人类手写的策展层——每一行都由用户负责。把插件自动沉淀的笔记写进那棵树，
等于让机器的猜测混进人类亲手维护的约束，用户下次读自己的规则文件时无法分辨哪句话是他说过的。

记忆还有成本问题：全文注入会把每次请求都撑大，条目越多边际收益越低。

## 决定

新建一个独立的记忆域，与人类记忆树完全分离：

- **域**：在 `ctx.storageDomain` 上新开一个域，名字 `orchestrator_memory`、版本 `1`、表 `entries`；
  记录 schema 是 zod 的 `{ id, text, tags, createdAt, updatedAt }`，`id` 同时是表键。
  写入走 `domain.table().put()`，落盘由宿主域负责。
- **上限**：条目 ≤ 200 条、渲染后的索引 ≤ 25 KiB，先到者为准。会越界的写入**明确报错并拒绝**
  （`entry-limit` / `byte-limit`），不静默截断、不静默淘汰；错误文案带当前值与上限，并要求先 prune 或缩短条目。
  `prune` 保留最近 N 条（缺省 100），被剪掉的条目不再出现在检索与索引里。
- **注入**：`ctx.systemPrompt.section()` 一段 `orchestrator:master-memory`（order 490，
  排在 500 的计划策略之前），内容只有首行标注 + 一行计数 + 每条一行的索引。
  首行写明「AI 记忆，非用户指令（插件自动沉淀，不是用户要求；与用户当轮指令冲突时，一律以用户为准）」。
- **开关**：`masterMemoryEnabled`，默认 `false`，在插件挂载时读取。关闭时不打开域、不注册注入段，
  既有会话的可观察行为为零变化。
- **人类树只读**：本功能不写 `~/.dsh` 下任何文件，也不接管 `AGENTS.md`。

## 替代方案与不选的理由

**直接写进 `~/.dsh/AGENTS.md` 或 `memory/topics/`。** 省掉一个域，但机器沉淀与人类约束混在一处，
用户无法审计自己的规则文件；这是 spec 明确排除的方向。
**拿会话日志当记忆。** 现成、可检索，但日志是「发生过什么」而不是「记住了什么」，
每次召回等于再读一遍历史，体积与 token 都不设上限。
**全文注入而不是索引。** 条目少时更好用，但上限就从「条目数 / 字节」变成 token 预算，每次请求都要付；
索引 + 检索入口把成本压到常数。
**超限时静默截断或淘汰最旧。** 用户永远不知道记忆丢了哪条；记忆层的可信度取决于「说不写就不写」。
**把记忆存在会话 cwd 下。** 那就变成按项目存储，跨项目的事实恰好丢掉了。

## 后果

- 记忆有两个来源要区分：人类的 `~/.dsh` 树与插件的记忆域，后者每次注入都带标注。
- 关闭开关时功能整体不存在：没有域、没有注入、没有可观察差异；打开需要重载插件（挂载时读取）。
- 索引是上下文不是策略，order 排在任何策略段之前。
- 上限让「记忆变便宜」成为可预期的承诺，代价是要有 prune 的调用方。
- 插件不信任表里既有数据的形状：既有条目已经超限时 `indexText()` 直接报错，而不是渲染一段超长文本。

## 与实现的偏差

1. **记忆没有模型侧的写入/检索入口。** `attachMasterMemory` 返回 façade，但 `apply` 里是
   `void attachMasterMemory(...)`，返回值被丢弃；插件也没有注册任何记忆工具。目前能写入记忆的只有拿到该
   façade 的代码（测试），主代理实际看到的是空索引。票 01 的验收在模块层（S1）证明，不在会话层；
   「主代理能写入、检索、精简」这一条还差一个入口。
2. **开关不做运行中翻转。** 与 `superviseEnabled` 等即时生效的键不同，本开关在挂载时读一次；
   翻转需要重新打开域并重注册注入段，不在该票范围。
3. **注入回调只收到 `AssembleContext`**（`{ scope?, signal? }`），拿不到记忆上下文，
   因此 section 注册时持有 façade、每次装配现读 `indexText()`；尚未打开或已失败时返回空串，由渲染层丢弃。
4. **没有 import 宿主的 `defineDomain`**：本仓库只声明三个宿主 peer，spec 用字面量声明，
   宿主 `open` 时仍按名字/版本/记录 schema 校验，语义等价。
5. **跨进程持久化由宿主域负责**：单测只用「临时 JSON 文件 + 新实例」证明写入→读回的契约，
   真实宿主重启后读回未验（spec 明确不测宿主集成）。
